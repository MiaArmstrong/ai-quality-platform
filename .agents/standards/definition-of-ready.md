# Definition of Ready

A work item is Ready when a contributor can begin without inventing critical requirements.

## Baseline

- [ ] Clear, actionable title
- [ ] Problem/context is described
- [ ] Scope is identifiable
- [ ] Acceptance criteria or expected behavior are objective
- [ ] Dependencies/blockers are identified
- [ ] Relevant configuration/feature flags are identified when known
- [ ] Required designs/specs are linked when applicable
- [ ] At least one concrete validation can be derived
- [ ] Major unresolved questions are documented
- [ ] Work is appropriately sized for its type

## Bug additions

- [ ] Environment identified
- [ ] Reproduction steps are deterministic
- [ ] Actual behavior stated
- [ ] Expected behavior stated
- [ ] Severity and priority evaluated separately
- [ ] Evidence attached/referenced when available

## Readiness verdicts

- **READY**
- **NEEDS INFO**
- **BLOCKED**

Do not mark Ready by guessing missing information.
